# Re-scoring prover attempts on a Slurm GPU cluster

## The command

On the cluster's login node, in a folder with **at least 30 GB free** (project or scratch space, not a small home directory), run:

```bash
git clone -b amu-rescore https://github.com/czajkowskis/optimizing-lean-agents-peano.git && bash optimizing-lean-agents-peano/helios/amu/run.sh
```

When the jobs finish, the result is `optimizing-lean-agents-peano/amu_stats.tar.gz` (about 1 GB). **Send that file to Szymon.** That's all.

If the cluster needs it, add options at the end of the command:

| Option | When to use it |
|---|---|
| `--partition NAME` | The script picks the first partition with GPUs; use this to choose a different one (`sinfo -s` lists them). |
| `--account NAME` | Your cluster requires a project or account for jobs. |
| `--gres gpu:a100:1` | Your cluster needs the GPU type spelled out. The default is `gpu:1`. |
| `--gpus 8` | You want to use more GPUs at once. The default is 4. |
| `--torch-index https://download.pytorch.org/whl/cu121` | The GPU driver is old and PyTorch can't use the GPU. The check job tells you if this happens. |

For example: `bash optimizing-lean-agents-peano/helios/amu/run.sh --partition gpu --account myproject`.

**Need:** NVIDIA GPUs with **at least 40 GB** of memory and bf16 support, for example A100, L40S, H100 or H200. Older V100s are too slow. The login node needs internet once, to download the model.

## What it does

`run.sh` runs on the login node for 10–20 minutes, mostly downloads:

1. **Checks** that `sbatch` exists and that all 16,640 attempts arrived with the clone.
2. **Creates a Python environment** in `amu_work/venv`, with PyTorch, transformers 5.9.0 and numpy. It uses any Python 3.10 or newer it finds; you can set `PYTHON=/path/to/python3.11` to choose one.
3. **Downloads the model** Goedel-Prover-V2-8B, about 16 GB, into `amu_work/hf_cache`.
4. **Submits three Slurm jobs,** each starting only after the previous one:

| Job | What it does | Time |
|---|---|---|
| `rescore-check` | Re-scores 200 attempts that were already scored on Helios and compares the results. If they differ, it stops and the next jobs are cancelled. Send its log (`amu_work/logs/check-*.out`) to Szymon. | 10–15 min |
| `rescore` | 4 jobs with 1 GPU each, splitting the 16,640 attempts between them. | about 1 h on H100, about 3 h on A100 |
| `rescore-collect` | Checks that every attempt has results, then packs them into `amu_stats.tar.gz`. | a few minutes |

Watch them with `squeue -u $USER`. The logs are in `optimizing-lean-agents-peano/amu_work/logs/`.

**If something fails or a job hits its time limit,** run the same `run.sh` command again from the same place. The Python environment, the model, a passed check and every finished attempt are all kept. It refuses to start while earlier jobs are still queued or running.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `no Python >= 3.10 found` | Load a newer Python (`module avail python`, then `module load ...`), or set `PYTHON=/path/to/python3.11` in front of the command. |
| `could not find a GPU partition`, or sbatch rejects the job | Add `--partition`, `--account` or `--gres` (see the options table). |
| The check log says `PyTorch cannot use the GPU` | Delete `amu_work/venv` and run again with `--torch-index` pointing at a lower `cuXXX`, for example `cu121`. `nvidia-smi` on a GPU node shows the CUDA version the driver supports. |
| `model download failed` | The login node has no internet. Download `Goedel-LM/Goedel-Prover-V2-8B` elsewhere, copy it to `amu_work/hf_cache`, and run again. |
| The check log says `DIFFERENT from Helios` | Send the log to Szymon and wait. |
| `OOM, skipped` in a `rescore` log | That GPU has too little memory for the longest attempts. Run again with `--partition` set to one with bigger GPUs; only the skipped attempts are processed. |
| The collect log says some attempts are missing results | Run the same command again. |

## What is computed (for reference)

The input `amu_data/token_ids/putnam85_rest_wp_8b/<id>.npz` holds one attempt's `prompt_ids` and `output_ids`. These are 65 PutnamBench problems × 256 attempts, generated by Goedel-Prover-V2-8B on the Helios cluster.

`helios/entropy/rescore.py` runs the model once over the prompt followed by the output. For every output token it saves the following to `<id>.stats.npz` as float16, using the model's full next-token distribution `p` at temperature 1:

- `entropy = -Σ p log p`, in nats
- `varentropy`
- `nll = -log p(chosen token)`

`helios/amu/verify.py` does the two checks: `check` compares the check-set results with Helios, and `done` makes sure every attempt has complete results.
